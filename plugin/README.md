# DSH 地区疫情周报 / Regional health reports

在会话右上角展开右侧栏，点标签栏的「+」打开指南，选择「地区疫情周报」，在聊天旁查看原生标签页。可查看所选地区的最新完整周、实际发布地区、样本与新发占比分档、探索性趋势，以及单独的全球官方来源快照。以服务端发布为准；低样本/无法发布不会显示为零。查看上级地区不表示本区上升。全球数据访问固定 Pages 站点，不是当地发病率。地图在新页打开（只携带公开地区代码）。地区选项以试点服务的有限目录为准。

## 构建、验证和手动安装

在此目录运行 `node build.mjs`、`node --test --test-isolation=none test/*.test.js`、`npm pack`（Windows PowerShell 用 `npm.cmd pack`）。不需要 npm install，无安装脚本。DSH 依赖使用宿主自带的 0.2.2-rc.5 API。生成的归档包含宿主入口、浏览器模块、配置补丁、图标与中英文元数据，不含个人数据。可审查归档后解压到固定目录；**在你决定安装时**，DSH → Plugins → Add plugin → 选择含 package.json 的解压目录或已构建的 plugin 源目录；按提示确认，检查插件行及启用状态，必要时刷新页面并在新会话验证。安装影响整个配置档。本文的构建/验证不会安装或更新现有配置档。

管理员在插件配置中设置 `backendUrl`（示例 `https://reports.example.org`；开发机 `http://127.0.0.1:8000`），可选 `defaultRegion`（六位代码，默认 `000000`）。仅接受 HTTPS 或 HTTP 回环；禁止 URL 用户名、密码、查询、片段及重定向。生产环境只应连接信任的服务，拒绝透明请求体/Authorization 日志。未配置后端仍可用随包地区目录浏览、阅读全球摘要并打开地图。面板先显示随包摘要。全球背景的固定在线端点是 `https://realJerryKing.github.io/global-epidemic-tracker/data/v2/epidemics.json`。成功请求、宿主已读缓存和随包摘要分别标为 `published`、`cached`、`bundled`；失败、无效数据和较旧发布分别标注，不会覆盖较新的有效摘要。`source_url` 仅在数据实际从该端点取得时填写（含已读缓存）；`publication_url` 始终指在线发布入口。官方栏注明快照构建时间和是否为历史迁移数据；这些时间不是病例报告期。社区周报与签到仍须配置后端。

## 使用与隐私

- 在面板选择地区。聊天中可请助手调用 `epidemic_snapshot`，可明确传 `region_code`；不传则用宿主进程最近在侧栏查看的地区，否则用管理员默认地区。共用汇总代码与短期内存缓存（一分钟；官方来源五分钟）。点击「刷新摘要」，或在工具中传 `refresh: true`，会绕过两层缓存并重新请求；没有后台签到或聊天推送。工具不提供签到、读取个人回答或凭据的参数。不同窗口共享宿主当前查看地区，按需明确传参。
- 个人签到只在已认证的宿主所有者界面操作。一次性邀请码请在面板输入，不要贴到聊天中。每周以中国标准时间的周一为键；选择本人地区、症状、可选的独立周边观察，勾选明确同意后提交。同周再次保存为修改。先选择周一再主动读取；撤回需要二次确认。已发布的匿名汇总不回滚。部署运营者须告知实际保留期、备份政策、管理员联系渠道，并限制邀请、网关与访问日志。默认保留含本周的八周。公开摘要与公共地图均不要求签到。
- 每个宿主配置档/后端地址只绑定一个参与者，不适用于多方共用同一个宿主所有者账号。密钥不存浏览器或插件配置：Windows 使用当前用户 DPAPI；支持 Electron safeStorage 的 macOS/Linux 仅在系统密钥存储可用时使用（拒绝 Linux basic_text）。仅密文进 DSH credentials 记录。不支持的宿主禁止绑定，公开摘要仍可用。凭据作用域与完整服务地址绑定，切换地址不会把令牌发送给新服务。此设计不能防止已控制操作系统用户或宿主进程的攻击者。丢失本机凭据请联系服务运营者；卸载不等于服务器端撤回。
- 应用不要求经纬度、不收自由文本、不向聊天写入个人签到。工具运行时可能记录公开查询地区与汇总。地图/官方来源通过 HTTPS 请求公共网站，站点可获常规连接信息。不要把健康详情发送给助手；保护自管服务和 DSH Host 的备份、代理及诊断记录。

## 公开 Pages 发布后的验收（已链接的 Desktop 插件）

1. 确认 v2 JSON 已发布；查看其中的 `last_update`、`summary.report_count` 和 `legacy`。在链接的插件源目录执行 `node build.mjs` 后，完整重启 Desktop 宿主（仅重新打开窗口未必重载 Host），再开新会话进入「地区疫情周报」。无需配置社区后端或签到。
2. 对同一地区连按两次「刷新摘要」（每次等待结果），确认官方栏显示「在线读取 · 公开 Pages v2」，公共 v2 数据链接指向上述固定端点。快照时间和记录数应与公开 JSON 一致；没有新发布时，两次可以相同。若两次之间发布了新快照，同一个宿主应立即显示新值，无需再次重启。
3. 也可用 `epidemic_snapshot` 指定同一 `region_code` 与 `refresh: true`，核对 `official.provenance` 为 `published`；紧接着普通读取应为 `cached`，不是新网络请求。离线刷新时，已读宿主显示 `cached`，未成功读过的宿主显示 `bundled`；两种都不应标为在线。不要测试生产签到。
4. 无配置档的自动检查：在 DSH Desktop 自带 Electron 的 Node 模式运行 `test/installed-smoke.mjs`；默认使用两个不同的 HTTP 响应夹具，确认一个已挂载实例会接收两份数据。发布后加 `--live`，向真实 Pages 发送两次请求并打印快照时间、记录数与来源。该检查不修改或打开配置档。

## 社区后端验收（仅自行安装的测试配置档）

打开侧栏面板、选择行政区并在新会话调用只读聊天工具核对报告周及发布层级。试验无后端、离线、未发布、上级替代；确认两种主题/窄屏、地图目标；用测试邀请码在面板内创建、修改、读取、撤回，核对聊天记录中无个人回答或邀请码。关闭后重开仅加载公开摘要，不自动读取私人记录。禁止使用真实参与者信息进行测试。
